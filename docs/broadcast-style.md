# 播报规则：怎么让 agent 说得像个人

这份文档是本项目里唯一"非代码"的部分，也是踩了坑才写出来的。

---

## 一、核心问题

AI agent 干完活，最自然的做法是把它的回复念一遍。**这是错的。**

一段典型的 agent 回复长这样：

> 我把 config.json 的 speaker 字段改成 `voices/wx/wx-C-clean-up4.mp3`，pitchShift 设成 1.06，然后重启了 9880 服务。日志里返回 `{"ok":true,"bootMs":21963}`，预设列表现在有两个。

念出来要 20 秒，听众得到的信息量约等于零 —— 里面没有一个词是他需要知道的。

**用户真正想知道的三件事**，按优先级：

1. **成了还是没成** —— 结果
2. **我要不要做点什么** —— 待办
3. **有什么变化或风险** —— 兜底

其余全是噪音。

---

## 二、硬规则

### 长度：30~60 字，1~3 句

- 压到 20 字（"弄好了"）→ 退化成公告，等于没说
- 超过 80 字 → 用户开始走神，和念正文没区别

### 内容：只留结论，过程全砍

必须砍掉的：

| 类型 | 例子 |
|---|---|
| 文件路径 | `D:\gsv\config.json` |
| 命令 | `python speak.py ...` |
| 参数 | `pitchShift 1.06` |
| 报错码 | `ERR_MODULE_NOT_FOUND` |
| 日志数值 | `bootMs=21963` |
| 中间发现 | "我先试了 A，不行，又试了 B" |

### 人称：用"你"指代对方要做的事

> ✅ "你可以再试一次了"
> ❌ "现在可以再次尝试该操作"

### 时态：讲结果，不讲动作

> ✅ "麦克风调好了，现在说话能识别了。"
> ❌ "我修改了阈值配置并重新加载了程序。"

---

## 三、三步起草法

**不要从回复正文里摘句子。** 摘出来的句子带着原文的书面语结构和上下文依赖，念出来必然生硬。

单独写一份，按这三步：

1. **这轮解决了什么 / 卡在哪** —— 一句话给结论
2. **用户接下来要做什么** —— 一句话；没有就略
3. **有没有欠账、风险、没做完的** —— 一句话；没有就略

揉成 1~3 句口语。

---

## 四、必须对上"本轮的重点"

不是随手挑一句结果。本轮回复的核心是什么，播报就该说什么：

| 本轮回复的性质 | 播报该说 |
|---|---|
| 做完了某件事 | 做完了什么 + 他要不要动 |
| 卡住了 / 需要他决定 | **在等他定什么** |
| 发现了风险 | 风险是什么 + 他要注意什么 |

**自检**：如果他只听这一句、不看屏幕，能不能知道"我刚做了什么"或"我要不要做什么"？答不上来就是没抓准。

---

## 五、顺序：先念，再写长回复

这条是踩坑换来的。

**错误做法**：写完长篇回复 → 收尾时想起来要播报 → 补念。

问题在于：长回复本身最消耗注意力，写完之后人（模型）已经没有余力再做收尾动作。实测在一个会话里因此**漏报三次**，都是"长回复 + 多工具调用"的轮次。

**正确做法**：把这一轮想完整（做什么、结果如何、要不要对方动手），**先调 `speak.py` 念结论**，再动手写正文。

顺序颠倒过来，播报就不再是"最后一步"：

```
旧：想清楚 → 写长回复 → （自检）→ 补念      ← 括号里这步会被跳过
新：想清楚 → 念掉 → 写长回复                ← 念不掉就没法往下写
```

### 但"先念"念的是结论，不是意图

| ❌ 念成行动预告 | ✅ 念成结果 |
|---|---|
| "我现在把本地分支整段去掉。" | "本地那条分支删干净了，现在只认云端。" |
| "我先查一下日志。" | "查完了，是念错了内容，不是没响。" |

判断标准：**念完这句，用户合上电脑去干别的，是不是已经知道结果了**。只知道"我要去做 X"，就是念错了。

### 两段式：写完之后再看一眼

第一次念的时候正文还没写，可能和最终结论有出入。所以正文写完后回头看一眼，**只在三种情况下补念**：

1. 结论变了（动手一查发现和预想的不一样）
2. 冒出新的待办（用户得去点什么）
3. 冒出新的风险（有东西坏了）

其余情况一律静默。**每轮响两次就是噪音** —— 第二段的价值在于兜住"第一段说错了"，不是复述一遍。

## 六、对照表

| ✅ 这样念 | ❌ 不要这样 |
|---|---|
| 桌宠嗓子换好了，两种音色都能切，你可以试试。 | 我把 config.json 的 speaker 字段改成 voices/wx/wx-C-clean-up4.mp3，pitchShift 设成 1.06，然后重启了 9880 服务… |
| 文档写完了，四篇都在产出文档那个文件夹里。 | 我新建了 01-dsh-pet本地模型thinking问题.html 等四个文件，大小分别是 13.6KB、17.5KB… |
| 麦克风调好了，现在说话能识别了。 | 日志里 peak 从 0.005 回到 0.223，超过阈值 0.0025，所以静音过滤不再触发… |
| 这个我搞不定，得你定用哪个音色。 | 关于音色选择，经我分析有若干因素需要考虑，首先是… |
| 查到原因了，是配置文件没生效，不是程序的问题。 | 我检查了三个可能的方向，第一步先看了日志，发现… |

## 七、什么时候不该播报

- 用户没要求，也没开启会话级授权 —— **一次都不念**
- 纯闲聊、确认收到 —— 除非用户明确要求每轮都报
- 用户已明确说停 —— 不要自己恢复

播报是给"用户在别处忙"的场景用的。用户在盯着屏幕时，声音是干扰。
